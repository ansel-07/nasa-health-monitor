## A01 — Invalid measurement domains reach storage and detection

**Where:** `pages/1_Check_in.py:351–380` (numeric form and finite-only validation); `core/episodes.py::_measurement`; `core/data.py::add_measurement`. Indicator definitions: `config/indicators.json`.

**Live reproduction, in a disposable session:**

1. Select Astronaut A and an environment, then Main Menu → Demo controls → Reset demo.
2. Open Check-in → Optic disc check.
3. Enter **99.5** for the left-eye ordinal grade and **0** for the right, then Record measurement.
4. The app accepts the pair and opens a `watch` episode requiring a repeat of the left grade. The chart includes the 99.5 reading.
5. In a separate reset, open Muscle strength, enter **-1**, and submit. This too is recorded and opens a repeat request. Trends subsequently displays `latest -1.0 N`.

These are intentionally invalid **test inputs**, not approved demo/medical values. Observed HTML numeric inputs had `step="0.01"` and essentially the full floating-point range. An ordinal grade is treated like an unrestricted continuous value, and finite-only checks do not protect a force-magnitude input.

**Expected:** reject values outside the indicator's declared measurement domain before writing rows, creating an episode or changing activity completion. Do not substitute normal values or clamp bad inputs silently.

**Cause:** all indicators share the same unconstrained floating-point widget. Neither the page nor the ingestion boundary validates an indicator-specific type/domain. Generator clipping choices are **not** clinical input limits and must not be copied into UI validation.

**Repair:** have Edu specify approved per-indicator input types/domains; have Ansel approve any metadata/schema addition. Use integer/discrete controls for approved ordinal/count fields, and validate again at the shared ingestion boundary. Preserve valid negative-valued indicators such as refraction; **do not apply a universal non-negative rule**. Any allowed grade set or clinical bound must come from Edu, not this report. Javi should apply the same validation to protocol measurement entry if applicable.

**Regression:** invalid ordinal fractional/out-of-domain and force-magnitude examples leave measurement count, episode count, pending queue and bars unchanged; an actionable error retains the entry for correction. Approved valid inputs still work, including signed refraction. Test UI and shared core entry points.

## A03 — Failing alarm reads are treated as “no alarms”

**Regression:** parameterize `OSError`, malformed-data `ValueError`, and `KeyError` in menu/list reads. Verify a visible error, usable navigation and retry after storage recovers; verify ordinary successful empty reads still render normally.

## A08 — Turning Voice off does not cancel current speech

**Where:** `core/mascot.py::build_html`, `if (!ANIMATE) return;` at line 143 precedes `speechSynthesis.cancel()` at line 178; `_voice_changed` clears last text only when turning voice on.

**Evidence:** instrumented the **app frame's** `speechSynthesis` methods with counters while retaining ordinary UI toggle/rerun behavior. Clicking the visible Voice label to enable it produced `{cancel: 1, speak: 1}`. Clicking again to disable it left `{cancel: 1, speak: 1}` while the switch was unchecked. No new cancel was called. This confirms the cancellation defect; audible TTS quality was not assessed.

**Expected:** muting must stop the active utterance immediately. Leaving for a screen with no mascot should not leave obsolete narration running.

**Cause:** the same text rerenders with `ANIMATE=false`, so the early return bypasses the parent synthesizer cancellation. Speech is deliberately owned by the persistent parent window, so replacing the mascot iframe is not a reliable cancellation policy.

**Repair:** explicitly cancel persistent speech on mute and when leaving mascot screens. Preserve the rule that unrelated same-text reruns do not restart narration. Use a small browser-side control/lifecycle mechanism; keep HTML/JS centralized in `core/mascot.py`.

**Regression:** with a stub synthesizer, start a long line, mute, and assert cancellation; navigate to Trends/Tutorials and assert no stale utterance. Re-enable and confirm the current line speaks once. Also manually test audible behavior in supported browsers.

**Repair:** cap face size by both parent height and available iframe width, preserve aspect ratio, and recompute on parent/window resize and relevant container-width changes. Keep resize observers stable and avoid a resize-feedback loop. Use max-width constraints as a fallback.

**Regression:** 320 × 1000, 390 × 844, landscape and desktop; assert SVG bounds fit within iframe width and no horizontal clipping. Resize an existing frame without a Streamlit rerun and verify recomputation. Recheck long subtitles and both sizes.
